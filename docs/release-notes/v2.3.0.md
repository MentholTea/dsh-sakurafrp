## 安装

```powershell
dsh plugin --profile desktop add dsh-sakurafrp -w
```

装不上就换这条（同为 2.3.0，取本 Release 的预构建包）：

```powershell
dsh plugin --profile desktop add https://github.com/MentholTea/dsh-sakurafrp/releases/latest/download/dsh-sakurafrp.tgz -w
```

## 新增：frpc 版本可见 + 手动检查更新

面板最上方新增一行 frpc 版本栏：

```
frpc  0.51.0-sakura-15.1   [检查更新]
```

- **版本常驻显示**。以前只有 frpc 出问题时才看得到版本（安装卡），装好且正常时
  整卡隐藏，用户根本不知道自己用的是哪个版本。现在短版本号常驻，悬停可看完整的
  `-V` 输出（含 built 时间与 commit）。
- **纯手动检查，绝不自动**。插件不会在启动、定时器、轮询或任何后台时机去查官方
  清单——只有点「检查更新」才发一次请求。这是刻意的：官方接口不该被无谓消耗。
- **频繁点击会被提醒**。60 秒内重复点击会被后端节流，界面明确显示
  「⏱ 别按太频繁，N 秒后再查」，而不是假装点了没反应。
- **确认有新版才出现更新按钮**。点「更新到 X」才真正下载替换。

## 更新的安全边界

替换本地 frpc 比全新安装风险更高——一旦把正在用的二进制搞坏，隧道当场断掉。
这里做了三件事：

1. **更新前先停 frpc**。Windows 上正在运行的 exe 无法被覆盖（EPERM/EBUSY），
   不先停就必然安装失败。
2. **失败要回滚，也要把 frpc 拉回来**。旧逻辑只在成功时重启；现在安装失败或异常
   时，如果更新前 frpc 正在跑，同样会自动恢复启动——否则用户看到的是
   「更新失败，而且隧道也断了」，故障被放大成两件事。
3. **下载链路沿用原有校验**：MD5 + 字节数 + `-V` 输出必须含 `-sakura-<构建号>`
   （防拿到原版 frp）。任一步不过，旧文件原样保住。

## 修了一个会白屏的 React Hooks 违规

`FrpcVersionBar` 最初把 `if (!healthy) return null` 写在 `useState` 之前。frpc
健康状态一变（装好、损坏、被换掉），渲染时的 hooks 数量就跟着变，React 会抛
`Rendered fewer hooks than expected` ——**整个设置面板白屏**。

项目的离线测试用的是自制 React 桩，不校验 hooks 规则，所以 628 项全绿也没抓到它。
修法是把所有 hooks 提到提前 return 之前，并新增 `update-check-test.mjs` 用结构断言
守住这条规则（剥掉注释后检查真实代码里 hooks 与 return 的先后）。

## 升级方式

```powershell
dsh plugin --profile desktop add dsh-sakurafrp@2.3.0 -w
```

装完重启 DSH。已配置的隧道、端口、密码、密钥都会保留，本地 frpc 不会被重装。
